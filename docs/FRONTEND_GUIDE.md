# 프론트엔드 팀 전달 - 백엔드 서버 연동 안내

## 1. API 서버 주소

```
http://1.201.116.47:8080
```

가비아 클라우드 서버에 배포되어 있고, `main` 브랜치에 백엔드 변경사항이 머지될
때마다 자동으로 재배포됩니다. 즉 별도 공지 없어도 최신 API가 반영돼 있다고
보시면 됩니다 (배포에 1~2분 정도 걸릴 수 있음).

## 2. API 문서 (Swagger)

```
http://1.201.116.47:8080/swagger-ui/index.html
```

전체 API 목록, 요청/응답 스키마를 여기서 바로 확인하고 브라우저에서 직접
호출 테스트도 가능합니다.

## 3. 인증 방식 (JWT)

1. `POST /auth/signup` — 회원가입
2. `POST /auth/login` — 로그인, 응답으로 JWT 토큰(`accessToken` 등) 반환
3. 이후 인증이 필요한 API 호출 시 헤더에 아래처럼 담아서 요청

```
Authorization: Bearer {로그인 응답으로 받은 토큰}
```

`/auth/**`, `/swagger-ui/**`, `/uploads/**` 경로는 토큰 없이도 접근 가능하고,
그 외 API는 전부 토큰이 필요합니다.

## 4. 로컬 개발 중 CORS 관련 안내

현재 백엔드는 `http://localhost:3000` 에서의 요청만 CORS 허용하도록 설정되어
있습니다. 만약 프론트를 다른 포트(예: Vite 기본값 `5173`)로 돌리고 계시면
브라우저 콘솔에 CORS 에러가 뜰 수 있어요 — 이 경우 사용 중인 포트를 백엔드
팀에 알려주시면 허용 목록에 추가해드립니다.

## 5. 파일 업로드/정적 리소스

업로드된 이미지 등은 아래 경로로 접근 가능합니다.
```
http://1.201.116.47:8080/uploads/{파일명}
```

## 6. 프론트 배포(HTTPS) 예정 시 꼭 미리 알려주세요

프론트가 나중에 Vercel/Netlify 등 **HTTPS 주소로 배포되면**, 지금처럼
HTTP 백엔드(`http://1.201.116.47:8080`)를 그대로 호출할 수 없습니다
(브라우저가 Mixed Content로 차단). 이때는 백엔드도 도메인 연결 + HTTPS
전환 작업이 필요하니, 배포 일정이 잡히면 최소 며칠 전에 백엔드 팀에게
알려주세요. 전환 후에는 API 주소가 `https://api.welli.com` (예시) 같은
형태로 바뀔 예정이며, 확정되면 다시 공지해드립니다. 구체적인 전환 절차는
백엔드 저장소의 `DEPLOYMENT.md` 8번 항목에 미리 정리되어 있습니다.

## 7. 문의

API 동작이 이상하거나 CORS/인증 관련 이슈 있으면 백엔드 팀에 바로
공유해주세요. 서버 로그로 원인 확인 가능합니다.
